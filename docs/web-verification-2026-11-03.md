## Исправления

- Стоимость рассчитывается по порциям (`quantity / quantityStep`): 200 г за 47,80 ₽ стоят 47,80 ₽. Учитываются выбранные добавки; для серверной корзины используется `supplementsTotal`, цена позиции и серверные компоненты скидки, сборки и доставки. Общая сумма обозначена предварительной оценкой, поскольку подтверждённого preview API нет. Для нескольких магазинов введён явный выбор группы.
- Гость видит и меняет корзину. При переносе удаляются только принятые позиции; остальные сохраняются, видны и доступны для повторного переноса даже при пустой серверной корзине. Ключ повторного запроса сохраняется до отправки и передаётся через клиент и proxy. Неоднозначные записи защищены от редактирования; повтор позднее 23 часов блокируется, поскольку backend хранит ответы 24 часа. Между вкладками перенос сериализуется Web Locks, где API доступен.
- Общая корзина использует ограниченный формат v2: магазин, ID выбранного товара/варианта, точное количество, добавки и количества каталожных добавок. Ограничения: 50 позиций, quantity ≤ 99999, ссылка ≤ 16000 символов. Неполные старые ссылки отклоняются с объяснением. Шаг проверяется по текущему товару; количество гостю добавляется одним действием. Принятые позиции импорта отмечаются на устройстве, неоднозначные запросы повторяются с тем же ключом в пределах безопасного срока.
- Выбор адреса сверяет магазин с реальным `stores?addressId`; адрес, шапка и корзина обновляют общий режим. Новый активный адрес также запускает согласование магазина. Быстрый просмотр, варианты, штрихкод и импорт передают магазин. Новая точка адреса больше не получает фиксированные координаты; требуется явная точка и подтверждение её соответствия тексту. Вложенная форма удалена.
- `useRemote` отделяет loading/error/empty и отбрасывает устаревшие ответы. Изменение даты и состава сбрасывает слот и обновляет интервалы; способ оплаты сверяется с серверным списком без выдуманного fallback. Ошибки корзины и интервалов имеют повтор. На 401 сбрасывается клиентская авторизация и серверная сессия; только явная CSRF-ошибка 403 повторяется после обновления токена. `no-store` имеет приоритет над revalidate.
- Бонусы читаются целыми единицами, используются userBalance/maxSpend/maxEarn; произвольное начисление 1% удалено. QR создаётся только из активного серверного payload. Бонусный блок доступен вне скрываемой мобильной колонки. Заказы отображают displayQuantity, добавки и сборку; polling ограничен 12 попытками и прекращается по конечному состоянию. Возврат без ID использует сохранённый `last-order`, а не произвольный последний заказ.
- Исправлены сохранение подраздела в пагинации и переход ко всем товарам родительской категории. Истории и баннеры читают реальные поля; добавлены баннеры главной и товары акции. Ошибки главной доходят до существующего error boundary с повтором, пустой каталог не показывает бесконечную загрузку.
- Сканер и QR-библиотека загружаются по необходимости. Убраны последовательные запросы детей категорий на главной и ожидание категорий перед поиском. Для карточек уточнены размеры изображений. На странице товара нет отдельной плавающей корзины поверх покупки; мобильный счётчик снова горизонтальный. Исправлены компоновка узкой строки товара, подпись цены за порцию и лишние отступы.

## Блокеры и непроверенные интеграции

1. Backend не сериализует подтверждённый итог preview и `canCancel`. Оформление из этой корзины недоступно, значение по умолчанию в `.env.example` — false. Локальная оценка не выдаётся за подтверждённую сумму. Разрешение отмены не выводилось из статуса наугад.
2. Нужна отдельная сверка разрешённого origin возврата с настройками платёжного провайдера и будущим адресом веба. Реальных SMS, входов, заказов, привязок карт и платежей не было. Авторизованные API, фактическая серверная идемпотентность и доставки проверены только по исходникам и заглушкам; транзакционность нескольких backend-действий выбора адреса/магазина не гарантируется вебом.
3. Геокодирование/геолокация с реальным адресом, реальные серверные фотографии, тяжёлые корзины, крупные деревья категорий и merchant callbacks не проходили сквозную приёмку. Большие ссылки могут превышать ёмкость QR — копирование ссылки остаётся отдельным способом передачи.
4. Автоматическая повторная отправка с истёкшим окном идемпотентности намеренно не выполняется: нужна ручная сверка с магазином. Ключи успеха общей корзины хранятся на том же устройстве; очистка хранилища удаляет эту защиту повторного импорта.
5. `npm audit --omit=dev` обнаружил существующие зависимости с advisory: Next — critical, sharp и source-map-js — high. Версии и lockfile не обновлялись в этом проходе; обновление и повторная приёмка нужны до размещения приложения.

Развёртывание не выполнялось. Production, backend, инфраструктура и чужая история не менялись.
